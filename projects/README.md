# Project context

These notes help Lookout review a change in the context of the user's intent
and the system it belongs to. They are working knowledge with sources and dates,
not authority to expand a task or a substitute for the current code.

An instance lists its projects, roots and records in `projects/INDEX.md`
(instance file, started from `templates/projects-index.md`). The records
themselves are `projects/<project>.md`. Neither is part of the kit.

## Maintaining context

Start a short record when a project receives substantive review or will be
reviewed repeatedly. Use [the template](../templates/project.md) selectively;
unknowns are acceptable. Do not inventory every repository or preload every
profile at the start of a review.

Keep the user's outcome, known system relationships, decisions and rationale,
important limits, and reusable lessons with evidence links. Identify whether an
entry comes from the user, inspected source, execution or inference. Give mutable
facts a last-checked revision/date. Recheck only facts the new decision depends
on. A prior approval applies to its captured target, not a later branch tip.

New user instructions take precedence over these notes. If current source
contradicts a recorded decision, establish whether that is intended before
turning either into a finding. Roadmap items are context, not task authorization.
Supersede stale notes explicitly; resolved defects belong in linked reports,
with only their useful lesson retained here.

Do not store credentials, raw login/configuration contents or personal data
unnecessary to review. Keep large evidence under `local/`. Task ownership remains
in `QUEUE.md`. Project notes are neither another task tracker nor a session
handoff.
